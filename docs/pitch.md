# Защита проекта: три минуты

[← README](../README.md) · [Демо](../examples/demo/README.md) · [Метрики](evaluation.md)

## 0:00–0:30 — проблема

«Разработчик может проверить, что приложение запускается, но не всегда видит, что казахский перевод звучит чуждо, игровой термин поменял значение или у имени игрока потерялись фигурные скобки. В тысячах строк это легко пропустить. Qazaq Loc QA делает такие проблемы видимыми до релиза».

На экране: обложка README и абзац о пользователе продукта.

## 0:30–1:10 — работающий инструмент

Запустить из корня проекта:

```bash
python locqa.py check --source examples/demo/intl_ru.arb --target examples/demo/intl_kk.arb --glossary examples/demo/glossary.csv --suspect-phrases examples/demo/suspect_kk.txt --out reports/demo.json
```

Открыть `reports/demo.html`, ввести `demoGreeting` в фильтр.

«Здесь пропала переменная `{pilot}`. Инструмент показывает ключ, русский оригинал, перевод, приоритет и точную причину. На другом примере он отмечает фиксированный казахский аффикс после динамического имени. Всего предусмотрено 11 типов; часть языковых проверок пока эвристическая».

Уточнить одной фразой: тексты специально написаны для открытого демо, данные организатора не публикуются.

## 1:10–1:50 — главная идея

На экране: схема архитектуры в README.

«Мы разделили поиск и исправление. Детектор решает, где подозрительное место, переводчик предлагает до трёх вариантов. Носитель выбирает один или пишет свой. Принятые решения идут в обучающий набор: из них можно создавать учебные ошибки и проверять детектор на новых строках. Игровой глоссарий сохраняет принятые термины».

«Эти модули уже есть, но они запускаются отдельными этапами. Наш следующий шаг — подтвердить смысловое качество и сократить ручную очередь на новых файлах».

## 1:50–2:20 — показать контроль результата

```bash
python locqa.py apply --source examples/demo/intl_ru.arb --target examples/demo/intl_kk.arb --corrections examples/demo/corrections.csv --only-reviewed --out reports/demo_reviewed_only.arb
```

На экране: `Applied 0 corrections`.

«В CSV есть два предложения, но оба ещё не проверены человеком. Программа сохраняет это различие. После реальной проверки изменённые строки получают метаданные, а аудит показывает, что осталось до сдачи».

## 2:20–3:00 — доказательства и развитие

Показать таблицу результатов README. Перед выступлением обновить числа по свежему аудиту; сейчас сохранён снимок на 31 октября 2026.

«Мы обработали 5 479 исходных ключей, подготовили очередь из 139 строк, подключили локальный переводчик и 86 кандидатов игрового глоссария. Технические нарушения плейсхолдеров в черновике уменьшились с 12 до нуля. 27 тестов проходят. Качество смысловых исправлений и recall на скрытом наборе мы пока не выдаём за измеренные. Следующий результат — проверенный корпус и независимая оценка двух контуров».

Завершающая фраза выступления: **«Наша цель — дать разработчику контроль над качеством языка, которого он сам может не знать, и улучшать этот контроль на проверенных игровых примерах»**.

## Короткие ответы жюри

| Вопрос | Ответ |
|---|---|
| Вы обучили свою языковую модель с нуля? | Нет. Есть собственный обучаемый классификатор и готовые локальные переводчики. Дообучение переводчика на принятых предложениях — следующий этап. |
| Почему два контура? | У поиска и исправления разные ошибки и критерии успеха. Разделение позволяет проверить их независимо. Преимущество конкретных моделей подтвердит эксперимент. |
| Что с игровым сленгом и идиомами? | Глоссарий уже помогает с согласованными терминами. Надёжная проверка идиом — целевая способность, которую ещё предстоит измерить. |
| Зачем носитель, если продукт для разработчика без знания языка? | Носитель создаёт эталон и решает спорные случаи. Автоматизация должна сокращать объём этой работы по мере накопления данных. |
| У вас 90–97% точности? | Это ориентир. Результат заявляется только для конкретной метрики на независимой размеченной выборке. |
| Работает без интернета? | CLI работает локально; переводчики — после отдельного скачивания весов и установки модельных зависимостей. |
| Есть сайт? | Сейчас пользовательский результат — CLI и HTML-отчёт в браузере. Единый интерфейс проверки включён в план развития. |
