## Соответствие критериям

Критерии взяты из предоставленного командой описания **Grand Mobile × Decentrathon 6.0, кейс 02**. [Документ организатора](https://docs.google.com/document/d/14gDrXuh0mVUSUjCKfF7_GmFLNbvrEMDQiA4diA4-EcI/preview).

| Критерий | Вес | Что предъявляем | Что ещё нужно измерить или завершить |
|---|---:|---|---|
| Детекция | 35% | Правила по 11 типам, объяснимый отчёт, обучаемый детектор. | Recall на примерно 100 скрытых ошибках по типу; precision на 100 случайных находках. |
| Качество исправлений | 35% | Отдельный генератор, выбор носителя, отметки изменённых строк, аудит. | Проверка носителями; слепое сравнение на 150 случайных изменённых строках по процедуре жюри. |
| Универсальность | 15% | Входные ARB через CLI, примеры с независимыми ключами, документация и тесты. | Прогон на новых наборах; расширение языковых правил за пределы казахского. |
| Объяснимость | 15% | `evidence`, `severity`, видимая неуверенность, HTML с поиском. | Ручная оценка полезности причин и числа ложных тревог. |

## Объём работы и качество измеряются отдельно

5 479 ключей, 139 строк в очереди, 105 строк с предложениями kazRush и 86 кандидатов терминов показывают объём подготовки. Они не являются оценками precision, recall, естественности или понимания сленга.

Сохранённый аудит чернового результата на 31 октября 2026: 97 изменённых ключей, 0 подтверждённых изменений, 4 пустых перевода; нарушений плейсхолдеров и ICU в этом аудите нет. Сборка окончательного файла зависит от проверки носителями. Публикуется только агрегатный снимок; сами строки кейса и отчёты остаются приватными.

## Протокол детектора

- Сначала зафиксировать подтверждённые правильные переводы и реальные ошибки с типами.
- Разделить данные до создания искажений. Текущий код удерживает совпадающие нормализованные русские строки вместе; для итогового эксперимента дополнительно исключить пересечение близких шаблонов.
- Выбрать пороги на проверочной части. Финальный тест не использовать для настройки.
- Считать precision как долю верных находок среди проверенных находок, recall — как долю найденных реальных ошибок среди всех размеченных ошибок; отдельно по типам.
- Показывать размер выборки, число исходных ключей, число ошибок, пропуски, ложные тревоги и долю `uncertain`.
- Результаты на реальных ошибках и искусственных искажениях публиковать отдельными таблицами.

Скрытый список организатора недоступен, поэтому recall по нему может посчитать только организатор. Публичное демо с 11 заранее известными дефектами проверяет воспроизводимость команд и объяснений.

## Протокол исправителя

Носители сравнивают исходный и предложенный перевод, оценивая сохранение смысла, естественность казахского, игровой словарь и пригодность для интерфейса. Для спорного контекста сохраняется комментарий. Принятие одного из вариантов, собственная формулировка и отклонение всех вариантов учитываются раздельно.

После отбора запускаются проверка структуры, применение с `--only-reviewed`, аудит и Flutter. Программный аудит не подменяет лингвистическую оценку. Три проверяющих, которым разданы разные части очереди, дают покрытие; для измерения согласованности нужна отдельная пересекающаяся выборка, проверенная независимо несколькими людьми.

Цель 90–97% можно объявить достигнутой только вместе с названием метрики, размером независимой выборки и методом оценки. Сейчас такого результата не заявлено.

## Проверки, которые можно повторить публично

```bash
python -m unittest discover -s tests -v
python locqa.py check --source examples/demo/intl_ru.arb --target examples/demo/intl_kk.arb --glossary examples/demo/glossary.csv --suspect-phrases examples/demo/suspect_kk.txt --out reports/demo.json
python examples/demo/verify.py
```

Локально проходят 27 тестов на Python 3.14. В CI задана матрица Python 3.10/3.14 на Ubuntu и Windows; её удалённый результат появится после публикации. Workflow проверяет код и синтетический пример, не отправляя данные организатора в артефакты GitHub.

## Перед финальной передачей организатору

- Завершить подтверждение переводов и терминов, объединить решения без повторов.
- Собрать `intl_kk_fixed.arb` и пересчитать число проверенных человеком изменений.
- Устранить блокеры аудита или явно подтвердить намеренно пустые строки с причиной.
- Согласовать три невалидных исходных имени ключей; нормализация временной копии не равна строгому прохождению неизменённого набора.
- Повторить `flutter gen-l10n` и сохранить точную команду, версию SDK и результат.
- Передать CLI, JSON/HTML-отчёты, глоссарий ru/kk/en, исправленный ARB и методику по каналу организатора.
- Обновить снимок метрик в README. Стоимость внешних LLM API в текущем запуске — 0; локальное вычисление не оценено в деньгах.
